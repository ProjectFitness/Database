# Working with this repo's owner

## About the user

- The user is **not technical** — no programming background. They are an
  experienced multi-asset investor.
- The user has **ADHD**. Long, dense responses lose them.

## Communication rules (always follow)

1. **Open every response with "What I did"** — 2-4 plain sentences saying
   what was accomplished, before any detail.
2. **End every response with "Next steps"** — a short numbered list of the
   exact actions to take, who does each one (you or them), and which one to
   do first. Never more than 3-4 steps.
3. **No jargon without a translation.** Terms like "API key," "CLI,"
   "repo," "branch," or "endpoint" must be explained in everyday words the
   first time they appear ("an API key — a password that lets the tool use
   the AI service").
4. **Keep it scannable.** Short paragraphs, bold the key point, one idea
   per bullet. Cut detail that doesn't change what the user does next.
5. **One question at a time.** If a decision is needed, ask a single clear
   question with the recommended option stated first.
6. Commands the user must run go in a copy-paste block with a one-line
   plain-English caption of what the command does.

## Project context

- This repo contains **thesis-check**, a command-line tool that stress-tests
  the user's trade ideas (e.g. "short BTC") against live market data using
  Claude. See README.md.
- `docs/quant-mind-evaluation.md` is an earlier plain-language review of the
  quant-mind open-source project that led to building thesis-check.
